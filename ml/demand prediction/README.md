# Demand Predict

Проект для прогнозирования спроса на вакансии по недельным временным рядам.

## Что делает проект

Цель проекта - предсказать количество вакансий по специальности на следующем периоде на основе:
- лагов целевой переменной;
- скользящих статистик;
- экспоненциальных и expanding-признаков;
- календарных эффектов;
- категориальных признаков по специальности.

## Данные

Первоисточник — [Data Jobs Люка Бароуса на Hugging Face](https://huggingface.co/datasets/lukebarousse/data_jobs): исторические вакансии 2023 года. `notebooks/eda.ipynb` читает нормализованный `data/raw/data_jobs_norm.csv` и агрегирует число записей по `job_title_unified` и неделе `job_posted_date`. Файл `data/aggregated/weekly_vacancy_counts.csv` совпадает с `backend/data/vacancy_data.csv`: 371 наблюдение за 2023-01-01–2023-12-31. Это число вакансий в исходном датасете, а не полный объём рынка и не текущие вакансии.

В [карточке исходного датасета](https://huggingface.co/datasets/lukebarousse/data_jobs/raw/main/README.md) указана лицензия Apache 2.0 (`apache-2.0`), проверено 2026-10-07. Промежуточный `data_jobs_norm.csv` не включён в репозиторий; версия и контрольная сумма исходной выгрузки не зафиксированы. Поэтому точное воспроизведение первоначального импорта не проверено. Общая [таблица происхождения данных](../../README.md#data-and-reviewer-workflow) описывает также источник навыков и синтетических профилей.


Основной источник данных - агрегированный недельный датасет с количеством вакансий по специальностям.

В процессе подготовки данных выполняются:
- сортировка по специальности и дате;
- генерация временных признаков;
- генерация лагов и rolling-признаков;
- разделение на train/test по времени;
- обучение моделей на обработанных признаках.

## Baseline

В качестве базовой линии использовалось двухнедельное скользящее среднее, то есть прогноз по `rolling_mean_2`.

В сохранённых результатах ноутбука `notebooks/modeling.ipynb` у `rolling_mean_2` WAPE около 0.1085. Это ориентир для данного временного разбиения и исторического датасета, а не оценка прогноза текущего рынка.

## Результаты моделей

Пробовались несколько семейств моделей:
- Linear Regression;
- Lasso Regression;
- Ridge Regression;
- Random Forest;
- CatBoost;
- LightGBM;
- XGBoost.

Также сравнивались разные наборы признаков:
- linear features;
- tree features;
- all features;
- версии с логарифмированием таргета.

Минимальный WAPE в [results/regression_report.csv](results/regression_report.csv) — **0.112001** у **LightGBM with linear features**. Эта же строка содержит MAE **221.25**, RMSE **386.86** и R² **0.9442**. Значение WAPE выше сохранённого baseline около 0.1085; отчёт не подтверждает преимущество этой модели над двухнедельным средним. Это проверка сохранённых результатов, без повторного обучения или нового временного теста.

## Возможные объяснения результатов

Ниже — возможные объяснения результатов и направления проверки. Само сравнение метрик не доказывает причину разницы и не устанавливает, какие изменения улучшат независимый временной тест.

### 1. Автокорреляция ряда

Автокорреляция недельных наблюдений может объяснять, почему простое скользящее среднее оказывается конкурентоспособным. Её влияние следует проверять на отдельных временных периодах и специальностях.

### 2. Перекрытие информации в признаках

Лаги, rolling- и expanding-признаки могут отражать похожий локальный сигнал. Чтобы оценить их дополнительный вклад, нужны сравнения наборов признаков на одинаковых временных разбиениях.

### 3. Риск подстройки под локальный шум

Более гибкая модель может подстраиваться под локальные колебания. Разница в сохранённых метриках совместима с этой гипотезой, но сама по себе не доказывает переобучение.

### 4. Ограниченный набор внешних факторов

Набор признаков опирается на историю самого ряда и календарь, без свежих сигналов активности работодателей или макроэкономики. Дополнительные источники могут быть полезны, но их вклад ещё нужно проверить.

### 5. Анализ ошибок baseline

Residual-анализ в `notebooks/residual_analysis.ipynb` помогает исследовать ошибки `rolling_mean_2`. Чтобы подтвердить устойчивость baseline, нужны несколько временных окон и проверка ошибок по сегментам.

## Вывод

В сохранённом сравнении минимальный модельный WAPE не лучше двухнедельного среднего. Внешние признаки, отдельные модели по сегментам и прогнозирование остатка — возможные эксперименты, без обещания улучшения. В приложении LightGBM обучается при инициализации сервиса на упакованных данных 2023 года; календарная дата сопоставляется неделе 2023 года. Это не live vacancy feed и не повторная оценка исследовательского test set.

## Структура проекта

- `notebooks/` - исследовательские ноутбуки и эксперименты;
- `src/experiments/` - код для baseline, отчетов и анализа ошибок;
- `src/metrics/` - метрики, включая WAPE;
- `configs/` - списки признаков для моделей;
- `data/` - сырые, промежуточные и обработанные данные;
- `results/` - итоговые метрики и отчеты моделей.

## Основные файлы

- `notebooks/feature_engineering.ipynb` - создание признаков;
- `notebooks/feature_selection.ipynb` - отбор признаков;
- `notebooks/modeling.ipynb` - обучение и сравнение моделей;
- `notebooks/residual_analysis.ipynb` - анализ остатков и baseline;
- `src/experiments/baseline.py` - расчет baseline-метрик;
- `src/experiments/report.py` - формирование отчета по моделям;
- `src/metrics/wape.py` - реализация WAPE.

## Как запустить

Исследовательский модуль использует собственные [pyproject.toml](pyproject.toml) и [uv.lock](uv.lock), с требованием Python **>=3.14**. Это отдельное окружение, не backend environment.

Из корня репозитория:

```bash
cd "ml/demand prediction"
uv sync --locked
```

1. Выбрать `.venv` этого модуля как kernel в редакторе ноутбуков. Jupyter editor/kernel должен быть установлен отдельно; он не включён в зависимости модуля.
2. Открыть ноутбуки из рабочей папки `notebooks/`, учитывая их относительные пути, в порядке:
	- `notebooks/feature_engineering.ipynb`
	- `notebooks/feature_selection.ipynb`
	- `notebooks/modeling.ipynb`
3. Посмотреть итоговые метрики в `results/regression_report.csv`. Ноутбук `eda.ipynb` для исходной агрегации требует отсутствующий `data/raw/data_jobs_norm.csv`; точное повторение первоначального импорта остаётся неподтверждённым. Запуск исследовательских ноутбуков может перезаписать производные данные и дополнить отчёты.

## Примечание

Этот проект ориентирован на сравнение временных моделей с очень сильным наивным baseline. Поэтому главный критерий качества здесь - не только ошибка модели, но и выигрыш относительно `rolling_mean_2`.
