# Demand Predict

Проект для прогнозирования спроса на вакансии по недельным временным рядам.

## Что делает проект

Цель проекта - предсказать количество вакансий по специальности на следующем периоде на основе:
- лагов целевой переменной;
- скользящих статистик;
- экспоненциальных и expanding-признаков;
- календарных эффектов;
- категориальных признаков по специальности.

## Данные

Первоисточник — [Data Jobs Люка Бароуса на Hugging Face](https://huggingface.co/datasets/lukebarousse/data_jobs): исторические вакансии 2023 года. `notebooks/eda.ipynb` читает нормализованный `data/raw/data_jobs_norm.csv` и агрегирует число записей по `job_title_unified` и неделе `job_posted_date`. Файл `data/aggregated/weekly_vacancy_counts.csv` совпадает с `backend/data/vacancy_data.csv`: 371 наблюдение за 2023-01-01–2023-12-31. Это число вакансий в исходном датасете, а не полный объём рынка и не текущие вакансии.

В [карточке исходного датасета](https://huggingface.co/datasets/lukebarousse/data_jobs/raw/main/README.md) указана лицензия Apache 2.0 (`apache-2.0`), проверено 2026-10-07. Промежуточный `data_jobs_norm.csv` не включён в репозиторий; версия и контрольная сумма исходной выгрузки не зафиксированы. Поэтому точное воспроизведение первоначального импорта не проверено. Общая [таблица происхождения данных](../../README.md#data-and-reviewer-workflow) описывает также источник навыков и синтетических профилей.


Основной источник данных - агрегированный недельный датасет с количеством вакансий по специальностям.

В процессе подготовки данных выполняются:
- сортировка по специальности и дате;
- генерация временных признаков;
- генерация лагов и rolling-признаков;
- разделение на train/test по времени;
- обучение моделей на обработанных признаках.

## Baseline

В качестве базовой линии использовалось двухнедельное скользящее среднее, то есть прогноз по `rolling_mean_2`.

Это оказался очень сильный baseline. В ноутбуке `notebooks/modeling.ipynb` видно, что `rolling_mean_2` дает WAPE около 0.1085, то есть ошибку уже очень низкую для этой задачи.

## Результаты моделей

Пробовались несколько семейств моделей:
- Linear Regression;
- Lasso Regression;
- Ridge Regression;
- Random Forest;
- CatBoost;
- LightGBM;
- XGBoost.

Также сравнивались разные наборы признаков:
- linear features;
- tree features;
- all features;
- версии с логарифмированием таргета.

Лучшие модели приблизились к baseline, но не смогли стабильно его обойти. По итоговой таблице в `results/regression_report.csv` лучшие WAPE находятся примерно в районе 0.1114-0.1117, что немного хуже baseline.

## Почему не удалось побить среднее за 2 недели

Причина в том, что для этой задачи двухнедельное скользящее среднее уже очень хорошо описывает динамику ряда.

### 1. Сильная автокорреляция ряда

Количество вакансий по неделе сильно зависит от предыдущих недель. Из-за этого простое скользящее среднее уже захватывает основную часть сигнала.

### 2. Большая часть новых признаков дублирует уже имеющуюся информацию

Лаги, rolling-статистики, expanding-признаки и календарные флаги помогают, но во многом отражают тот же локальный тренд, который baseline уже улавливает.

### 3. Сложные модели добавляют шум вместо устойчивого сигнала

Когда baseline уже очень сильный, более гибкие модели часто начинают подстраиваться под локальные колебания и шум, а не улучшают прогноз на независимом временном тесте.

### 4. Не хватает внешних факторов

В данных нет явных внешних драйверов спроса: например, сезонных событий, изменений рынка труда, активности работодателей или макроэкономических факторов. Без таких признаков улучшить короткое скользящее среднее сложно.

### 5. Ошибка baseline уже низкая

По residual-анализу видно, что остатки после `rolling_mean_2` заметно меньше исходного ряда и объясняют небольшую часть общей вариативности. Это означает, что модель пытается улучшить уже очень качественную точку отсчета.

## Вывод

Итоговый вывод такой: модельный пайплайн работает, но на текущих признаках не удается стабильно обойти двухнедельное скользящее среднее. Для заметного улучшения нужны либо внешние признаки, либо отдельные модели по сегментам, либо прогнозирование остатка относительно baseline.

## Структура проекта

- `notebooks/` - исследовательские ноутбуки и эксперименты;
- `src/experiments/` - код для baseline, отчетов и анализа ошибок;
- `src/metrics/` - метрики, включая WAPE;
- `configs/` - списки признаков для моделей;
- `data/` - сырые, промежуточные и обработанные данные;
- `results/` - итоговые метрики и отчеты моделей.

## Основные файлы

- `notebooks/feature_engineering.ipynb` - создание признаков;
- `notebooks/feature_selection.ipynb` - отбор признаков;
- `notebooks/modeling.ipynb` - обучение и сравнение моделей;
- `notebooks/residual_analysis.ipynb` - анализ остатков и baseline;
- `src/experiments/baseline.py` - расчет baseline-метрик;
- `src/experiments/report.py` - формирование отчета по моделям;
- `src/metrics/wape.py` - реализация WAPE.

## Как запустить

1. Активировать окружение.
2. Открыть ноутбуки в порядке:
	- `notebooks/feature_engineering.ipynb`
	- `notebooks/feature_selection.ipynb`
	- `notebooks/modeling.ipynb`
3. Посмотреть итоговые метрики в `results/regression_report.csv`.

## Примечание

Этот проект ориентирован на сравнение временных моделей с очень сильным наивным baseline. Поэтому главный критерий качества здесь - не только ошибка модели, но и выигрыш относительно `rolling_mean_2`.
